# Docs and publishing

## Generated documentation

Docs under `docs/` in the Registry's required layout are generated by
[`tfplugindocs`](https://github.com/hashicorp/terraform-plugin-docs) from
your schema descriptions and `examples/`.

```
docs/
  index.md
  resources/widget.md
  data-sources/widget.md
examples/
  provider/provider.tf
  resources/example_widget/resource.tf
  data-sources/example_widget/data_source.tf
```

- Add the generator as a tool dependency (`tools.go`) and a `//go:generate`
  directive:

  ```go
  //go:generate go run github.com/hashicorp/terraform-plugin-docs/cmd/tfplugindocs
  ```

- Run `go generate ./...` after any schema/example change.
- **Never hand-edit `docs/`** — the next generation overwrites it.
- Make CI fail if generated docs are stale:

  ```yaml
  - run: go generate ./...
  - run: |
      if [ -n "$(git status --porcelain docs/)" ]; then
        echo "docs/ is out of date - run 'go generate ./...' and commit" >&2
        git diff docs/
        exit 1
      fi
  ```

- `MarkdownDescription` on every attribute is what makes the generated
  page useful; a bare schema yields a bare doc.

## Registry publication

Prerequisites, once per provider:
1. A GitHub repo named `terraform-provider-<type>`.
2. A GPG key (private key + passphrase) to sign release checksums.
3. The HashiCorp GitHub App installed on the repo, linking it to your
   Registry namespace (a one-time manual step initiated from the
   Registry).

The Registry address is `registry.terraform.io/<namespace>/<type>`,
where `<type>` is the repo suffix — independent of the resource prefix.

## GoReleaser

`.goreleaser.yml` cross-compiles the provider for the platform matrix the
Registry expects (linux/darwin/windows × amd64/arm64 and others), builds
a zip per platform, and produces `terraform-provider-<type>_<version>_SHA256SUMS`
plus a GPG signature of it.

```yaml
builds:
  - env: [CGO_ENABLED=0]
    goos: [freebsd, windows, linux, darwin]
    goarch: [amd64, "386", arm, arm64]
    ignore:
      - goos: darwin
        goarch: "386"
archives:
  - format: zip
checksum:
  name_template: 'terraform-provider-example_{{ .Version }}_SHA256SUMS'
  algorithm: sha256
signs:
  - artifacts: checksum
    args: ["--batch", "-u", "{{ .Env.GPG_FINGERPRINT }}", "--output", "${signature}", "--detach-sign", "${artifact}"]
```

The release workflow:

```yaml
on:
  push:
    tags: ["v*"]
permissions:
  contents: write
jobs:
  goreleaser:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<sha>
        with: { fetch-depth: 0 }
      - uses: actions/setup-go@<sha>
        with: { go-version-file: go.mod }
      - uses: goreleaser/goreleaser-action@<sha>
        with: { args: release --clean }
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          GPG_FINGERPRINT: ${{ steps.import_gpg.outputs.fingerprint }}
          GPG_PRIVATE_KEY: ${{ secrets.GPG_PRIVATE_KEY }}
          GPG_PASSPHRASE: ${{ secrets.GPG_PASSPHRASE }}
```

- The Registry fetches release assets from the GitHub Release; the
  manifest file and signed checksums are what it verifies.
- Always run `goreleaser check` in CI to catch config drift before a tag
  triggers a release.

## `terraform-registry-manifest.json`

A small file at the repo root declaring the protocol versions the
provider supports:

```json
{
  "version": 1,
  "metadata": { "protocol_versions": ["6.0"] }
}
```

Include it in the release artifacts so the Registry knows the wire
protocol.

## Versioning

Tag releases as `vX.Y.Z` (SemVer, see [`../../semver/SKILL.md`](../../semver/SKILL.md)).
A provider's public API is its schema: removing/renaming an attribute or
changing its type is a breaking change. Adding an optional attribute is
not.

## Local development (dev_overrides)

```hcl
# ~/.terraformrc
provider_installation {
  dev_overrides {
    "registry.terraform.io/example/example" = "/Users/me/go/bin"
  }
  direct {}
}
```

```bash
go build -o "$(go env GOPATH)/bin/terraform-provider-example" .
cd examples/local && terraform plan    # skip `terraform init` under overrides
```

Terraform prints a dev-override warning banner during plan/apply —
expected, not an error. Keep `examples/local/` for this workflow and
`examples/registry/` for real published usage, so the two never get
confused.
